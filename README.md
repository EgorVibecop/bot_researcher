# Радар вакансий для исследователей

Telegram-бот, который сам следит за вакансиями и присылает новые в личку.

Ищет по названию вакансии: **UX / CX / Product / Market Research**, researcher,
ресерчер, исследователь, исследования, исследователь пользовательского и
клиентского опыта, социолог, юзабилити, CustDev, глубинные интервью,
фокус-группы, качественные и количественные исследования.

Источники: **hh.ru**, **Хабр Карьера**, **getmatch** и **телеграм-каналы**
(последние подключаются отдельно, см. ниже).

Одна и та же вакансия, найденная в нескольких сервисах, приходит одной
карточкой — со ссылками на каждый сервис, где она нашлась. Архивные
и всё старше трёх месяцев не показывается.

По умолчанию присылает **только удалёнку** — офис и гибрид включаются кнопками
в настройках. Каждая вакансия приходит один раз, дубли по городам склеиваются.

## Развёртывание на хостинге (основной способ)

1. Залей папку `jobbot` в репозиторий на GitHub.
2. В панели хостинга (bothost.ru и подобные) укажи:
   - **Git URL** — ссылка на репозиторий, ветка `main`
   - **Команда запуска** — `python bot.py`
   - **Переменная окружения** `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
3. Deploy.

Базу бот создаёт сам при первом запуске, ничего заранее выполнять не нужно.

### Чтобы история не сбрасывалась при передеплое

В базе лежит список уже отправленных вакансий. Если хостинг даёт постоянный
диск, укажи путь к нему:

```
DB_PATH=/data/jobs.db
```

Без этого бот тоже работает, но после передеплоя может прислать заново то,
что уже показывал.

### Остальные переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BOT_TOKEN` | — | обязательный токен от @BotFather |
| `ADMIN_ID` | — | твой Telegram id, открывает команду `/admin` |
| `CHECK_INTERVAL_MINUTES` | `30` | как часто опрашивать источники |
| `SEARCH_PERIOD_DAYS` | `7` | за какой период тянуть вакансии с hh |
| `DB_PATH` | рядом с кодом | путь к базе |
| `HH_TOKEN` | — | токен приложения hh.ru, если зарегистрируешь (см. ниже) |

## Запуск на своём компьютере

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python bot.py
```

Токен вставить в `.env`. Если бот уже крутится на хостинге — останови его там,
иначе Telegram будет отдавать обновления то одному, то другому.

## Что умеет бот

| Команда / кнопка | Что делает |
|---|---|
| `/start` | подписаться, сразу показать свежую подборку |
| 🔍 Найти сейчас (`/find`) | внеочередная проверка источников |
| ⚙️ Настройки (`/settings`) | формат работы, регион, минимальная ЗП, категории, источники, режим |
| 🔑 Ключевые слова (`/keywords`) | свои ключи и стоп-слова |
| `/search текст` | разовый поиск по hh.ru, например `/search service design` |
| ⏸ Пауза (`/pause`, `/resume`) | временно перестать присылать |
| 📊 Статистика (`/stats`) | сколько прислано, сколько в базе, по источникам |
| `/reset` | забыть историю отправок и прислать всё подходящее заново |

Под каждой вакансией — кнопка «🚫 Скрыть компанию»: убирает из ленты все
вакансии этого работодателя.

### Настройки

- **Формат работы** — удалённо / гибрид / офис, чекбоксы. По умолчанию только
  удалённо. Если у вакансии несколько форматов (офис + удалёнка), она пройдёт
  по любому из отмеченных.
- **Регион** — вся Россия / Москва / Санкт-Петербург. Удалёнка проходит
  фильтр региона всегда.
- **Минимальная зарплата** — кнопка перебирает 0 → 100k → … → 300k. Отдельным
  переключателем можно скрыть вакансии без указанной зарплаты.
- **Категории** — UX, CX, Product, Marketing, соц. исследования и общая
  «Исследования» (всё, что прошло по ключам, но не попало в тематику).
- **Режим** — присылать сразу или дайджестом утром. Ночью (23:00–08:00) бот
  молчит и копит.

## Как устроен отбор

Три шага, все в `matching.py`:

1. **Исследовательское ядро.** Если в названии нет корня «исследова», research,
   ресерч, социолог, юзабилити, CustDev и т.п. — вакансия отбрасывается сразу.
   Это отсекает «UX-дизайнера» и «маркетолога».
2. **Стоп-слова.** Режем то, что тоже зовётся исследованием, но нам не нужно:
   научные сотрудники, лаборанты, химики, агрономы, клинические исследования,
   рекрутеры-ресечеры, операторы колл-центров, «пешие исследователи» (курьеры),
   товарка на маркетплейсах, а также аналитика данных (data analyst,
   дата-аналитик, системный/бизнес-аналитик) и продажи.
3. **Категории.** Что прошло — размечается тегами UX / CX / Product /
   Marketing / соц. исследования, по ним работает фильтр в настройках.

Добавить или убрать ключи можно двумя способами: кнопкой 🔑 в боте (действует
только для тебя) или правкой списков в `matching.py` (для всех).

## Про источники

- **hh.ru.** Официальное API с 2025 года отдаёт `403` без токена приложения,
  поэтому бот читает JSON-состояние обычной страницы поиска — тот же ответ,
  который рисует выдачу в браузере. Поиск идёт строго по названию вакансии
  (`search_field=name`), плюс отдельный проход с фильтром «удалённо».
  Если зарегистрируешь приложение на [dev.hh.ru](https://dev.hh.ru/admin) и
  положишь токен в `HH_TOKEN`, бот автоматически переключится на официальное API.
- **Хабр Карьера.** Разбор карточек выдачи, поиск свободным текстом — весь
  мусор отсекается уже своими фильтрами.
### Телеграм-каналы как источник

Телеграм-бот не может читать канал, в котором он не администратор. Поэтому
каналы читаются от имени обычного аккаунта через Telethon:

```bash
pip install telethon
```

Затем задай переменные (api_id и api_hash берутся на https://my.telegram.org):

```
TG_API_ID=1234567
TG_API_HASH=...
TG_CHANNELS=@hr_jobs,@ux_vacancies
```

Первый запуск попросит войти по телефону — создастся файл сессии `*.session`.
Он даёт доступ к аккаунту, поэтому в git не попадает (см. `.gitignore`).
Без этих переменных источник просто выключен, остальные работают как обычно.

Из поста бот вытаскивает название (первая содержательная строка), зарплату
и формат работы. Даты у постов есть, поэтому фильтр по свежести работает
и здесь.


- **getmatch.** Открытый JSON со свежими офферами, там в основном IT, но
  исследовательские роли иногда попадаются.

Запросы к hh идут по очереди с паузой: параллельная пачка ловит `429`.

## Возможные проблемы

- **Бот не отвечает** — не задан `BOT_TOKEN` в панели хостинга или в `.env`.
- **Приходит одно и то же** — база не переживает передеплой, укажи `DB_PATH`
  на постоянный диск.
- **Вакансии перестали приходить с hh** — в логах будет `403` или `429`.
  Хостинг мог попасть под фильтр: помогает `HH_TOKEN` (официальное API).
- **Слишком много лишнего** — добавь стоп-слово кнопкой 🔑 или пропиши его в
  `STOP_PATTERNS` в `matching.py`.
- **Ничего не приходит** — проверь настройки: с «только удалёнка» + высокой
  минимальной зарплатой подходящих вакансий может не быть вовсе.
